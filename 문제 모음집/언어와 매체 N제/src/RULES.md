## 옮겨 적기
- 쪽 이미지로 확인: `pdftoppm -r 200 -png -f 17 -l 18 r0N.pdf 출력` 후 PIL로 단을 잘라 확대해 Read. 텍스트 레이어(`pdftotext`)는 참고만 — **옛한글·기호·밑줄은 텍스트 레이어에서 빠지거나 틀린다**(예: 3월 원본은 ‘ㅎ’이 맞는데 착각하기 쉬움). 옛한글은 첫가끝 조합 자모(U+1100~11FF, 아래아 U+119E 등)로 적고 이미지와 하나하나 대조.
- 원본 글자 그대로. 밑줄 `<u>…</u>`, 굵게 `<b>…</b>`, 기호(㉠ ⓐ ㉮ Ⓐ [A])는 원본 위치 그대로, 기호와 밑줄 사이 한 칸(`㉠ <u>…</u>`).
- 지문은 문단마다 \n. [A] 같은 묶음 괄호는 `{A}…{/A}`(mk_r01 참고).
- 지문 묶음: `{'rng': '35～36', 'works': [{'label':'', 'lines': …, 'author': ''}], 'questions': [...]}`. 지문 없는 단독 문항은 `{'rng': None, 'works': [], 'questions': [...]}`. 원본의 묶음 안내([35～36] 등) 범위를 그대로.
- <보기>·<학습 활동>·<자료> 등 상자: 글줄만 있으면 `'bogi': {'title': '<보기>', 'text': '줄\n줄'}`(ㄱ. ㉠ 등 항목 줄은 자동 내어쓰기; ‘이름: 대사’ 줄은 화자 굵게·내어쓰기). 표·◦ 목록·예 상자가 있으면 `'html': [('<보기>', '<div class="bl dot">◦ …</div><table class="jr">…</table>')]`(mk_r01의 BOGI36·JARYO36·ACT38 형식, 클래스 dot/pi/bnote2/jr/ph, 예 상자는 `<span class="bx">예</span>`).
- 대화·지문 상자(39번 같은 것): `'extra': {'title': '', 'text': '…'}`.
- 선지 5개(기호 빼고). 표 모양 선지(ⓐ/ⓑ/Ⓐ Ⓑ Ⓒ 칸)는 `'pair_head': ['Ⓐ','Ⓑ','Ⓒ']`, 선지는 `'칸1 / 칸2 / 칸3'`.
- 발문의 ‘않은’ 등 원본 밑줄은 `<u>않은</u>`. [3점] 표시 그대로.

## 정답·해설(원본에 없음 → 직접 풀어서 작성)
- 모든 선지를 지문·문법 지식으로 검증해 정답을 정한다. 정답이 둘이거나 없으면 보고.
- `ex[str(번호)] = {'answer': '③', 'correct': '…', 'wrong': [['①','…'],…(정답 뺀 4개)]}` — 화면에는 `035 답 ③` / **이게 정답!** correct / **왜 답이 아니지?** wrong 으로 나온다.
- correct: 왜 정답인지(적절하지 않은 것을 묻는 문항이면 왜 적절하지 않은지) 2~4문장. wrong: 선지마다 1~2문장, 왜 적절한지/틀렸는지. 예시를 구체적으로(분석 ‘흐르-+-어+가다’, 발음 [일른], 음운 변동 이름 등). ‘~이다/~한다/~므로 적절하다’ 체, 문장 끝 마침표. 인용은 ‘ ’.
- 단(단 나눔): 두 번째 쪽이 한 단에 몰리면 오른쪽 단으로 보낼 문항에 `'colbrk': True`(mk_r01의 39번처럼). 내가 조판 보고 조정하므로 신경 쓰지 않아도 됨.

## 추가 주의(7~11회에서 생긴 문제)
- 발문·선지·해설(stem/choices/correct/wrong)과 bogi/extra의 text에는 html 태그를 넣지 않는다(`<u>`, `<b>`, `<box>`만 가능). 한자는 그대로 쓰면 조판 때 자동으로 감싼다. `<span class="hj">`는 html 상자 안에서만.
- 선지가 원본에서 두 줄이면 `\n`으로 나눈다(예: 원래 문장\n→ 바꾼 문장). pair_head 표 칸 안에서도 `\n` 줄바꿈 가능, 긴 칸은 자동 왼쪽 정렬.
- 제목 없는 상자는 html의 제목을 ''로(제목 줄 없이 그려짐).
- 정답이 둘로 갈릴 수 있으면 정답 해설 끝이나 해당 오답 해설 끝에 ‘※ …로 보면 …’ 안내를 넣고 보고한다.
